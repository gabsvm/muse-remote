# Publish a safe Muse Remote demo

A short demonstration helps first-time users understand the project before installing software.

## Suggested 20–30 second sequence

1. Show the PC running the loopback bridge (no token visible).
2. Show the Android or PWA client connecting through a test connection.
3. Open a **fictional disposable session**, show a short synthetic prompt and display a simulated tool event.
4. Show an approval decision and the return to the latest message.
5. Finish with the open-source repository URL and a beta disclaimer.

## Before publishing

- Use dedicated dummy test data, not genuine account sessions or private source files.
- Hide the terminal token, QR image, pairing fingerprint, private device address and company hostnames.
- Disable desktop notifications and crop status bars if they show personal information.
- Never imply the CLI or a paid Muse subscription is included.
- Record actual supported UI; don't use a mocked visual as proof that a live function was tested.
- Only include assets with documented redistribution rights.

When a sanitized recording exists, link it from README and specify the platform and version shown. The current repository deliberately does not claim to have a verified recording.
